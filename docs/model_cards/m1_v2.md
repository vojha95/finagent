## What changed from v1

Same features, classifier, C grid and temperature fitting as `m1-tfidf-lr-v1`; only the dataset
changed (`rows_v1` -> `rows_v2`, same 17,112 rows):

- **Unit line (issue #42, BC12).** Every row now has a unit (v1: 4,387 rows had none: COP, HD,
  MCD, PFE, PG, TGT, UNP, CAT CF, DE FY2023–25; CVX and T in validation). Unit text is not a
  feature, so this changes E1 fields, not the classifier's inputs.
- **Concept map (issue #43).** PP&E including finance-lease right-of-use assets maps to `ppe_net`
  and `LongTermDebtAndCapitalLeaseObligations` to `long_term_debt`: 105 rows move from OTHER to
  an item (train 36 `ppe_net`, 49 `long_term_debt`; validation 15 and 5), 0 AMBIGUOUS. These are
  training-label changes.

C = 64 again (macro-F1 still rising slightly at 16 -> 64: 0.833 -> 0.834); T = 1.300 (v1 1.448).

## Field-level result (E1, validation)

Field accuracy 0.889, company-bootstrap 95% CI [0.838, 0.939], 961 fields; M0 on the same
dataset 0.770 [0.654, 0.876]. McNemar M0 vs M1: 28 fields right only under M0, 142 only under M1,
exact p = 1.5e-19. v1 was 0.680 [0.399, 0.900] on 941 fields. Details and the v1/v2 comparison:
`docs/e1_validation.md`.

**Optimistic.** Validation chose C and fitted T, and the title-block unit rule (pattern B, issue
#42) was found on validation companies (CVX, T): no train filer uses it. The held-out run
(Phase 8) is the unbiased measure.

## Known failure modes (validation, v2)

1. **Same wording, different concept by filer (issue #28).** "Total operating expenses" is
   `total_costs_and_expenses` for AMZN, CVX, T but `operating_expenses` for six train filers
   (15 fields MISSED); "Income before income taxes" is `pretax_income_before_equity_method` for
   AMZN, CVX (10 fields, F1 0). Text alone cannot separate them.
2. **Operating cash flow total worded unusually** (MSFT "Net cash from operations", ABT "Net Cash
   From Operating Activities", NKE "Cash provided (used) by operations"): called OTHER, 15 fields.
   Still the largest single item gap (19/34 fields; M0 29/34).
3. **Parent vs consolidated.** `net_income` vs `net_income_including_nci` and
   `equity_attributable_to_parent` vs `total_equity` confused both ways (T total equity, NKE parent
   equity: 10 fields); CVX basic/diluted EPS rows under "Net income attributable to ..." read as
   `net_income` (10 rows, no field cost).
4. **Unlabelled or gross rows.** MRK's unlabelled gross PP&E total ranks above the net row (5
   WRONG_ROW); CVX "Properties, plant and equipment, at cost" (gross, finance-lease ROU concept
   before depreciation) predicted `ppe_net` (5 rows, no field cost).
5. **Concept-map and label-noise rows still labelled OTHER.** NKE "Inventories"
   (`InventoryFinishedGoodsNetOfReserves`, left unmapped by decision), T "Inventories"
   (`PrepaidExpenseCurrent`, 9.5 audit), CVX "Long-term debt"
   (`LongTermDebtAndCapitalLeaseObligationsIncludingCurrentMaturities`, not in the approved
   mapping): M1 predicts the item, counted as false positives.
6. **Sign.** AMZN income tax shown as "(provision)": 5 SIGN fields (issue #27, Phase 5).
7. **Borderline rows move on retraining.** MRK's IS "Sales" (no parent header) was P(revenue)
   0.79 under v1 and is 0.41 under v2 (OTHER 0.58): 5 revenue fields lost although no revenue
   label changed. A bare one-word label is fragile for a text-only model.

## Intended use

- Document-channel line-item classification for US 10-K face statements (IS, BS, CF) in the
  FinAgent pipeline; top-3 probabilities feed the Correlation Agent's re-pick (8.8).
- Current M1 of the model ladder (replaces `m1-tfidf-lr-v1` for comparison with M2 and M3).

## Out of scope

- Notes tables, segment tables, quarterly data, non-US filers or IFRS statements.
- Any row the row builder did not produce (statements incorporated by reference, BC10;
  div-layout filings, issue #31).
- Using probabilities as calibrated outside the validation distribution.
- Claims about held-out accuracy: not yet run (Phase 8).
