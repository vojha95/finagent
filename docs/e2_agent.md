## 1. Setup

- **Evaluation mode.** The agent sees each company-year's rows, M1 top-3 predictions and the filing only: no tags, no tag checks (`D:<item>`), NCI by BC23 (no NCI only when no total-equity or net-income-including-NCI line is read and no IS or BS row label mentions a noncontrolling or minority interest, #110). Its loop, guardrails and settle rule are the product ones (`docs/correlation_agent_v1.md`): an action must bring a failing check within tolerance (#103); a swap needs M1 p >= 0.1 and a row no other item reads (#109); a face-block total's component items are inputs of the checks that use it (#111).
- **Answer key.** E1's: the tag channel's verified value for each face item (BC8), BC13 twins and BC14 keys. The scorer reads it after the agent has finished; the harness also reads it to choose injections. The agent never does.
- **Clean.** The real M1 v3 readings of every company-year.
- **Corrupted.** One injected error per company-year through the in-memory edit hook: types rotate over the sorted company-years (wrong_row, rescale_1000, flip_sign, second_candidate); the item is drawn at random (seed 20261125) among the scored face items the document channel read correctly (strict, no BC13), and the injection must make it wrong. If the assigned type cannot be applied to any eligible item, the next type in the rotation is used. 40 company-years injected.
  - `wrong_row`: the item read from another row of the same statement that is not one of its top-3 candidates and holds a different value (random).
  - `rescale_1000`: its own row's value × 1,000.
  - `flip_sign`: its own row's value with the sign reversed.
  - `second_candidate`: the highest-ranked other candidate row (item in its top-3) whose value is wrong.
- **Metrics.** *Visible*: the injection makes a check fail that does not fail the same way (same check, same residual) on the clean readings. *Located*: the injected item is itself an input of a failing check, so the agent can suspect it (a formula-derived value expands to its inputs, and a face-block total to the items read on its component rows, #111). *Detected*: the agent flags the injected item (CORRECTED or REVIEW). *Year flagged*: the agent flags some value of a newly failing check, so the year is not passed silently. *Corrected*: the injected item's final value is the true value. *Wrongly changed*: a scored field right before the agent and wrong after. Field accuracy is E1's (BC13 on), before = the agent's starting readings (with the injection), after = the final readings; McNemar is exact on the paired fields. Identity pass rate: PASS share of the evaluation-mode checks computed. Intervals are 95% percentile bootstraps over companies (2000 draws).
- **Priors.** Rescale and flip prior 0.5 [Guessing]; sensitivity at 0.25, 0.75 (both priors set together).

### Two runs, and why e2-0002 is not blind

- **e2-0001** is the first E2 result: Correlation Agent v1, with #102 and #103, before #108-#111. Its files are kept unchanged in `runs/e2-0001/`; its report is docs/e2_agent.md at commit 9e4ed05.
- **e2-0002** is agent v1.1. It adds the reviewer decisions on #109 (swap guards), #110 (BC23 NCI label rule) and #111 (face-block components as check inputs). #108 confirms existing product-mode code and does not touch E2. These decisions were recorded on Vineet's behalf and are pending his confirmation.
- **Not blind.** #108-#111 were decided after seeing e2-0001 on this validation split, and #109, #110 and #111 each target cases found there:
  - #109: T FY2022;
  - #110: T FY2025;
  - #111: NKE FY2023 and MRK FY2021.

  e2-0002 reruns the same companies, filings, answer key, seed and injections (injections.csv is identical). Its gains over e2-0001 are therefore partly fitted to these 40 company-years and are not an unbiased estimate of the agent on new filings.
- The validation companies had already been examined in 5a/5b (#103, #107). A blind figure needs company-years not used in the design; held-out companies are never run in E2, by rule.

### Main limitation: most injected errors are invisible to the identity library (#112, deferred)

- In both runs, **29 of 40 injected errors (73%)** leave every evaluation-mode check exactly as on the clean readings. Only about 45% of scored fields enter any computed check (43% in e2-0001, 46% with #111). No agent working from this identity library can detect those errors, however it ranks or guards its actions.
- What the checks don't see:
  - Accounts payable, long-term debt, SG&A, interest expense, PP&E and capex (beyond sanity) enter no identity.
  - Total current liabilities enters one only through a face-block total liabilities (#111).
  - Parent net income enters no check once the consolidated line is read.
  - I7 is an ordering, so a flipped or swapped component usually still satisfies it.
  - I10 and I11 need tag-channel operands, so they are not computable in evaluation mode (#99).
- **Decision (#112, reviewer, pending Vineet): deferred.** No new identities in Phase 5.
- **Future work** (each a design change, Appendix B style):
  - face-block subtotal checks: current assets and current liabilities = the sum of their face rows;
  - cross-statement ties: D&A on the income statement or cash flow; capex against the PP&E movement;
  - document-cell operands for I10, so it can run with tags hidden.
- Until then, E2's detection and correction rates measure the agent only on the roughly quarter of errors the identities can see.

### Limits

- 8 companies and 40 company-years, so the bootstrap intervals over companies are wide. The by-type rates (n = 10 each) mostly reflect which items the draw landed on.
- One injection per company-year, only into items the channel read correctly (strict). The answer key is E1's tag key; the agent never sees it.
