## 1. Setup

- **Evaluation mode.** The agent sees each company-year's rows, M1 top-3 predictions and the filing only: no tags, no tag checks (`D:<item>`), NCI by BC23. Its loop, guardrails and settle rule are the product ones (`docs/correlation_agent_v1.md`), including #103 (an action must bring a failing check within tolerance).
- **Answer key.** E1's: the tag channel's verified value for each face item (BC8), BC13 twins and BC14 keys. The scorer reads it after the agent has finished; the harness also reads it to choose injections. The agent never does.
- **Clean.** The real M1 v3 readings of every company-year.
- **Corrupted.** One injected error per company-year through the in-memory edit hook: types rotate over the sorted company-years (wrong_row, rescale_1000, flip_sign, second_candidate); the item is drawn at random (seed 20261125) among the scored face items the document channel read correctly (strict, no BC13), and the injection must make it wrong. If the assigned type cannot be applied to any eligible item, the next type in the rotation is used. 40 company-years injected.
  - `wrong_row`: the item read from another row of the same statement that is not one of its top-3 candidates and holds a different value (random).
  - `rescale_1000`: its own row's value × 1,000.
  - `flip_sign`: its own row's value with the sign reversed.
  - `second_candidate`: the highest-ranked other candidate row (item in its top-3) whose value is wrong.
- **Metrics.** *Visible*: the injection makes a check fail that does not fail the same way (same check, same residual) on the clean readings. *Located*: the injected item is itself an input of a failing check, so the agent can suspect it (a formula-derived value expands to its inputs; a face-block total's rows do not). *Detected*: the agent flags the injected item (CORRECTED or REVIEW). *Year flagged*: the agent flags some value of a newly failing check, so the year is not passed silently. *Corrected*: the injected item's final value is the true value. *Wrongly changed*: a scored field right before the agent and wrong after. Field accuracy is E1's (BC13 on), before = the agent's starting readings (with the injection), after = the final readings; McNemar is exact on the paired fields. Identity pass rate: PASS share of the evaluation-mode checks computed. Intervals are 95% percentile bootstraps over companies (2000 draws).
- **Priors.** Rescale and flip prior 0.5 [Guessing]; sensitivity at 0.25, 0.75 (both priors set together).

## Notes (hand-written, 2026-11-25)

**What the run shows.**

- **Clean readings: no significant gain, as in October (blueprint 8.8 "prior result").**
  - The agent acts on 4 of 40 company-years. It fixes 3 tax signs (AMZN FY2021-FY2023) and wrongly changes 1 value (T FY2025 net income, #110).
  - It leaves 12 values on REVIEW. 6 of those were right readings: false alarms, but nothing is changed.
  - AMZN FY2024-FY2025 go to REVIEW rather than being fixed (#113).
- **Injected errors: the agent repairs what the identities can see, and the identities see little.**
  - It corrects 8 of the 9 errors it can locate, with one action each.
  - Every visible error leaves the year flagged (11 of 11), so none passed silently.
  - But 29 of 40 injected errors move no evaluation-mode check, so no agent working from these identities could catch them (#112). Examples:
    - Accounts payable, current liabilities, long-term debt, SG&A and interest enter no identity.
    - Parent net income enters no check once the consolidated line is read (CVX, T).
    - I7 is an ordering, so a flipped or swapped receivable usually still satisfies it.
  - The per-type rates (10-30%) mostly reflect which items the draw landed on. The intervals overlap widely.
- **Safety.**
  - 1 wrongly changed value on clean readings and 2 on corrupted ones. All three are AT&T, with two causes:
    - a coincidental swap that reads one row for two items (#109);
    - the BC23 no-NCI assumption when M1 misses the NCI lines (#110).
  - No company-year used more than 1 action, and the 5-action limit was never reached.
- **Prior (rescale / flip 0.5 [Guessing]).** Results are identical at 0.25 and 0.75. Under #103 a failing check rarely has more than one admissible action, so the ranking never decides. The prior is therefore *untested* by this data, not validated.
- **Field accuracy after the agent.** Corrupted condition: 86.4% → 87.3% (McNemar 2/11, p = 0.022). That is 11 fields fixed: 8 injected and 3 AMZN tax signs. The clean before-value (90.5%, 971 fields) reproduces E1 m1-v3 exactly, as a harness check.

**Limits of this evaluation.**
- 8 companies and 40 company-years, so the bootstrap intervals over companies are wide.
- The validation companies were looked at during Phase 5a/5b (AMZN, MRK and T traces drove #103 and #107). This E2 is out-of-sample for M1, but not fully blind for the agent's design. Held-out companies were not run, per the rules.
- One injection per company-year, only into items the channel read correctly (strict). The answer key is E1's tag key, which the agent never sees.

**Open decisions:** #108 (confirm "same row"), #109 (one row, one item and/or a probability floor for swaps), #110 (BC23 and net income), #111 (face-block components as check inputs), #112 (identity coverage).
